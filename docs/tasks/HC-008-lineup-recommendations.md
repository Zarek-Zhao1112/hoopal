## 目标与授权范围

用户希望先讨论并确定需求，已接受：一个阵容一个档案的游戏编队体验；每名队员以体型 / 擅长 / 可选弱项标签描述，未选能力按一般；保存多份本地阵容；只推荐进攻；提供三套优先候选、原因、人员职责与内置动画联动。编辑页移除，防守库保留独立浏览，APK 继续本地离线。

需求和三页效果图已批准；实现、自动检查与独立审查完成，手机已覆盖安装并冷启动 1.5.0。新功能真实手机操作仍待人工验收，安装与静态截图不代替保存、输入法或旋转测试。

## 实际分工

主 agent 事前冻结档案结构、推荐输出及 UI 回调，按以下文件边界实施：

| 负责人 | 模块 | 责任 |
| --- | --- | --- |
| 主 agent | app.js、workspace、平台整合、版本、文档与 E2E | 移除编辑、映射与切换上下文、最终联调和交付 |
| engine | shared/lineups.js、shared/recommendations.js、data/recommendations/、相关单测 | 输入规范、职责分配、推荐规则与解释 |
| ui | index.html、app.css、frontend/src/lineups/ | 档案卡、逐人标签配置、推荐列表及三屏布局 |
| 主 agent | storage/lineups.js、lineup-session.js 及专项测试 | 新键、快照队列、读取 / 损坏保护、推荐来源与双键切换 |
| 独立 reviewer | 只读 | 需求一致性、规则案例、存储安全与过期映射 |

四个并发 agent 分别负责整合 / 存储、数据 / 算法、UI、只读独立审查；审查人不参与实现。共享配置仍归主 agent。

## 接口和约束

- 推荐只引用同人数内置进攻 ID，输出排名、理由、缺口及职责号 → 档案成员 ID 一对一映射；不修改模板数据、Play、球权或路线格式。
- 新档案存储与内置选择 / 旧个人库清理隔离；只保存档案和 ID，不恢复个人战术。
- 表单上限、容量、默认值和模块名是需求文档中的实现约定，并非用户逐项指定；如需调整须同步文档与验收。
- 先页面方案，再冻结数据和推荐接口后开发；规则人工审核与独立审查为必需环节。
