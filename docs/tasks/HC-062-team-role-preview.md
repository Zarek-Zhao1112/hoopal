# HC-062 · 3v3 球员角色与本队站位网页预览

状态 `completed`（独立交互预览）。用户要求沿用当前球搭界面，预览三位球员统一设置主角色，以及按体型挑选进攻战术后自动安排本队站位。关联现有[体型挑选](../design/tactic-body-selection.md)与[战术角色定义](../design/tactic-role-assignments.md)。

原型复用项目的冰川蓝玻璃样式、球队球衣、木地板球场、播放器、3v3 进攻模板和体型分类。在预览内为每套战术指定三个位置偏好的通用角色，以稳定棋子 ID 对应示例队员。角色可重复或留空，三人各有一个战术位置。手动交换只作用于当前演练，重选战术或应用角色后重新分配。更换体型后确认战术才应用。

范围是独立网页。队员、角色、体型与交换都只留在当前页面内存，无正式存储接口或 APK 改动。验收关注角色面板、两套以上战术的实际换位、体型过滤、球衣号码与步骤同步、手机竖屏布局。

## 交付与证据

后续原型加入 3v3 / 4v4 切换及应用内角色选项。每次在一行内展开，支持重复选择和稍后设置。两队独立保留当前网页中已保存的角色、体型与所选战术。4v4 沿用同一组三种角色并给四个战术位置分别安排球员，训练场用两列展示四个站位。

后续版已用 Edge 渲染两张 390×844 画面，确认 4v4 角色展开和四个站位完整显示。原型截图位于 `artifacts/design/team-role-selector/4v4-prototype.png`。

用户确认继续细分 4v4 角色。3v3 保留持球发起、掩护策应、空间终结。4v4 提供持球发起、掩护配合、接球策应、空间终结，并按 9 套现有 4v4 进攻战术的具体职责更新站位偏好。两种人数都支持重复选择及暂不设置。本轮交付网页原型。

更新后的本地网页返回 200。Edge 在 390×844 下核对两种人数的角色选项，并将两人都设为接球策应，在「高低位配合」中分配到翼侧入口传球与高位策应。

运行 `node scripts/preview-training-library.mjs 4191` 后，访问该端口上的 `/frontend/previews/team-roles/index.html`。复用当前项目本地预览服务，脚本打印的默认路径仍是原战术库预览。

本地 HTTP 返回 200。Edge 验证了保存角色后高位挡拆换人、球场号码、训练播放、当前战术临时交换、两大一小目录过滤、低位分切卡内播放与选用、步骤全文号码转换。390×844、360×640、844×390 下训练场无页面纵向滚动，球场与播放键可见。本机 Chrome 在调试启动前退出，改用 Edge 验证。另见[独立静态审查与修复](../reviews/HC-062-team-role-preview.md)。
