## 问题记录格式

每条发现记录：编号、优先级、位置、触发条件、实际影响、证据、建议或修复、负责人、复验方式和状态。

优先级含义：

- P0：影响核心使用且需立即处理的严重故障。
- P1：数据丢失、核心流程错误等高影响问题。
- P2：具体条件下的功能、兼容或交互问题。
- P3：可选改进，不影响本次必需验收。

问题状态使用 `open`、`fixed`、`verified` 或 `deferred`。`fixed` 表示已有修复，`verified` 表示已复验；`deferred` 必须写明影响、原因和后续任务，不能只写“以后处理”。

## 审查结论

审查结论分别写代码结果和验证范围：未发现新的问题、已修复哪些问题、剩余什么问题、哪些环境没有验证。没有发现问题时如实记录即可。

代码审查闭环不代表 APK 已完成所有设备验收。原生 mock、浏览器模拟、构建成功、安装成功和真机功能测试分别记录。原生功能修改后，按风险安排必要设备检查；文字更正只检查内容与链接。
