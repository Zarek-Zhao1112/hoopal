# HC-076 独立审查记录

## 范围

只读审查 3v3 主副角色 schema、旧角色兼容、战术位置分配和当前前端变更。审查人未参与实现。

## 证据

- `shared/team-roles.js`：3v3 与 4v4 分开呈现 `space` 含义；九套 3v3 进攻定义主、副角色偏好；角色只分配给唯一队员。
- `shared/lineups.js` 与 `frontend/src/storage/lineups.js`：3v3 副角色验证；旧 `space` 仍是有效 ID；损坏角色字段独立隔离。
- 单测：257 项通过；战术目录完整性脚本检查 26 套 / 91 个职责位及分类通过。

## 发现与处理

- 审查发现 HC-076 初稿把“主角色必选”写成要求，但现有界面和保存接口允许主角色为空，只有副角色时也能参与匹配。用户随后明确前端设计暂后讨论。为保留当前可选行为并避免未经讨论改变配置约束，修正任务文档：主角色仍可暂不设置，副角色选填。没有引入新配置 UI。
- 复验：`shared/team-roles.js` 仍优先最大化主角色命中，其次副角色命中，再按阵容排列解决平局并填补空位；空主角色行为与现有保存规则相符。
- 复审：`saveMainRoles` 旧 payload 省略 `secondaryRole` 时保留档案值，显式空字符串/null 时清除，队员身份和版本校验仍有效。若省略副角色同时将主角色改成与原副角色相同，最终 `validateLineup` 会拒绝写入，不会落盘。
