## R1 · P2 · 进度输入被暂停重绘覆盖

位置：artifacts/design/new-tactics-preview/preview.js:90 的 timeline-scrub input listener，及 pause→paint 对 range.value 的同步。

主控在收口后新增真实 CTA / range / 速度 / 全文控件检查，复现将 range 设 500 并触发 input 后，progress 为 0.009 而非 0.5。旧 listener 先 pause；pause 调用 paint，把 event.target 所指输入节点的 value 改回原进度，再读取该 value，导致用户 seek 被旧状态吞掉。影响为拖动进度不能跳到用户选择位置；此前逐步 API 和完整播放通过不覆盖这条真实输入路径。

主控只修改该 listener：先读取并 clamp 成局部 requested，再 pause，随后 progress=requested、paint。数据、篮球路线及其他 UI 无变更。reviewer 已只读复核，并在 VM 执行真实 pause 函数与真实 input listener；paint 桩模拟实际 range.value 重绘副作用。内存恢复旧顺序精确得到 progress=.009 / value=9，修后为 progress=.5 / value=500，同时 playing=false、旧 rAF=7 已取消、raf=null；0 / 125 / 999 / 1000 输入另均得到对应比例。此为确定性事件 / 状态夹具，不是完整 DOM 或浏览器复验。

reviewer 已核对 controls-verification.json：主控修后四尺寸真实 CTA 进入演练、range input 后 progress=.5 / playing=false、速度及全文弹窗检查通过；各弹窗无整页溢出、列出控件中心命中，errors / remote / storage 均为空。状态：`verified`。既有 32 布局 / 六套完整播放的证据对未改路径仍有效，不把它们冒充本次 range 修复的复验；修复证据是此处独立夹具和四尺寸 controls 专项。
