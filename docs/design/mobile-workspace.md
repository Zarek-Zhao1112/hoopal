# 一屏工作台设计

日期：2026-10-22。在实现前建立。任务：[HC-005](../tasks/HC-005-mobile-workspace.md)。

## 用户目标

手机竖屏为默认使用方式；旋转手机时球场使用更大的可用高度，平板横屏可同时查看战术库和步骤。用户不希望为播放、编辑或选择战术上下滚动页面。

## 布局与交互

- 手机竖屏：紧凑标题 / 人数 / 更多；居中完整球场；当前步骤短讲解；播放与进度；固定底部演练 / 编辑 / 战术库。编辑页显示绘图工具、步骤选择和讲解编辑入口，暂停动画后操作。库页独立分页选择，成功载入后返回演练。
- 手机横屏：球场利用左侧可用全高，右侧固定控制区含讲解、播放和页面入口；不拉伸或裁掉球场。切编辑时可用工具和步骤入口。
- 平板横屏 / 桌面：左库、中场、右步骤，播放在球场下方；工具在编辑模式可见。库、步骤仍分页，避免内容数量推动页面高度。
- 超长讲解：主界面摘要，点开对话框分段阅读；笔记输入允许文本框内部光标滚动，不要求滚动整个页面。菜单收纳导入导出和其他低频操作。
- CSS 使用动态视口及安全区；窄屏键盘弹起时不能仅因高度变小误判为手机横屏。所有关键按钮有可触摸尺寸，屏幕尺寸不足时优先减少装饰和辅助说明。

## 数据及平台

页签、分页和弹窗为视图状态，不写进 Play。保留原草稿、用户库和平台存储。切换页签需提交未失焦输入，切到库或编辑暂停动画并结束手势；加载战术继续沿用已有保存保护。

Android 返回键先关闭弹窗 / 菜单，再处理动画或编辑，再从库 / 编辑回演练，最后遵循原返回桌面行为。网页 Escape 同样关闭最上层弹窗。旋转不重建业务状态、不丢失编辑。

## 验证

浏览器验证至少 360×640、390×844、844×390、1024×768、1280×800 和桌面；检查 document 高度、各主要区域边界与关键操作可见性，不能只检查横向溢出。覆盖 40 项库 / 60 步边界、分页加载、长讲解、编辑 / 手势 / 播放、旋转状态与对话框关闭。独立审查后构建新版离线 APK，实际设备证据另记。

## 实施结果

已按上述范围完成。正文分页最终采用对话框实际空间测量，修复固定字数无法处理大量换行的问题；旋转时保留字符偏移。手机步骤为一排六个编号，完整讲解编辑使用独立弹窗；平板卡片内部用 flex 保证分类徽标不被裁掉。

61 项检查、六屏三视图及大数据量 Chrome 回归通过，独立审查闭环。1.2.0 已覆盖安装到手机，实际截图确认一屏竖屏与旧草稿恢复。真实键盘、返回键、旋转和触控仍待设备确认。详见 [任务与验证](../tasks/HC-005-mobile-workspace.md) 和 [独立审查](../reviews/HC-005-mobile-workspace.md)。
