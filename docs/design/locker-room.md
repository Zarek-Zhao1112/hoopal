# 冰川蓝更衣室与玻璃导航

日期：2026-10-23。状态：已实现、审查/浏览器验证，1.7.0 已安装至新机，完整原生交互待验。任务：[HC-010](../tasks/HC-010-locker-room.md)。用户确认 `artifacts/design/locker-room-glacier-v2-glass.png` 后开始实现。

## 目标与边界

阵容使用冰川蓝墙面、灰蓝金属柜、银灰铭牌和浅枫木长凳，采用体育游戏拟物风格。一次聚焦一位队员，左右滑动时连续柜位/球衣/场景一起移动；相邻柜位可露边。球员详情随选中成员更新，配置与进攻推荐操作固定。演练保留木地板、清晰橙蓝棋子与场边控制。底部三个页面使用悬浮磨砂玻璃导航和蓝色选中胶囊。

3v3/4v4、所有既有档案、推荐、内置战术和离线功能保留；不增加评分或商业系统、不恢复战术编辑。效果图的透视、号码位置不作为修改模板坐标依据。布局以手机竖屏一屏、横屏放大球场、平板多栏和真实控制可达为准。

## 接口与状态

- 阵容仍沿用 `createLineupUI` 的 root/onAction/onInspect 和既有创建/选择/配置/推荐回调。新选中球员属于每档案的临时 UI 状态，不写入磁盘；切队和删除后按成员 ID 校验/收敛。
- 左右滑动只在更衣室场景处理，水平阈值、主方向判断、pointercancel 及末端限位防止纵向/按钮误触；提供前后按钮和位置指示作为替代。切换不改变阵容成员，不触发保存/推荐来源变化。遵守 reduced-motion。
- 保留完整姓名/标签点击查看、配置分区、未保存草稿与写失败保护；从当前球员进入配置时选中同一成员。
- 全部视觉资源打包到本地，动态姓名/号码为文本/SVG；不把整张效果图当网页。玻璃效果使用本地 CSS，backdrop-filter 不可用时有足够不透明的浅底回退。
- 不改存储键、Play、推荐与生命周期协议，无数据迁移。原生仅同步启动主题/图标色与版本。

用户更换的新机为 M2101K9C / API31，实际 WebView 96。实现必须为 dvh 提供 vh 回退；输入压缩采用真实 input 焦点类，不仅依赖 :has；非当前柜位用 aria-hidden、禁用/移出 tab 序列及 pointer-events 隔离，不仅依赖原生 inert。玻璃背景有不支持滤镜时的可读回退。首次安装不自动写入演示档案。

## 分工与验证

主 agent：app.css、index.html、版本/平台外观、文档、E2E/设备与最终集成。ui：lineups/ui.js、styles.css、必要更衣室绘图模块。engine：app.js 的纯绘图及 board/appearance.js，统一蓝银配色、木地板、棋子厚度/阴影，保留坐标/球权/导出快照。interaction_design：独立只读审查。

验证实际水平触摸/按钮切换、两人数/边界/取消、动态名字号码标签、配置指向与档案隔离；复用六尺寸全部子页、长文本、20套动画、PNG/JSON、离线及存储回归。检查玻璃导航不遮挡控制，低高度输入聚焦与横屏导航仍可用。升级前后对用户档案/选择文件作只读哈希比对；安装/静态截图与真机手势操作分开记录。
