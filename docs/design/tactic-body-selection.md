# 按球队整体体型挑选战术

2026-11-02用户批准[HC-055效果](../../artifacts/design/body-type-tactic-concept/overview-v1.png)，实现见[HC-056](../tasks/HC-056-body-type-tactic-release.md)。取代HC-054逐人确认作为前置操作；保球队身份、现有26套动画、旧计划及离线能力。

## 体验

更衣室「挑选战术」→整体体型→分类战术/玻璃选单→训练场。三人体型是一大两小/两大一小/体型接近；四人是一大三小/两大两小/三大一小/体型接近。卡片只描述人数和相对体型，不直接给内外线位置或能力。每套可属于多个分类，显示一条配合说明，不显示最适合、胜率、能力分或自动评估。

球队入口固定当前球队人数；独立战术库可按自身人数浏览，在其他人数下显示浏览模式，不写当前球队。没有球队也能从库浏览。保存偏好按profileId，先在页面选卡，点击「查看战术」才保存；失败保选择及重试，成功后下一次沿用。改名、号码与NBA球队保偏好，人数不同另建球队。底栏离开关闭挑选页，再点「战术库」回列表。

候选严格按mode/kind/bodyType过滤，不以列全或隐藏错误替代校验。进攻/防守分区独立，局部玻璃选单显示当前名称、简短用途与勾选，220ms展开/160ms收回。取消/同项仅操作预览，主Play和进度保持；真实进入训练场才可靠解除旧来源并载入。动画仍按1/2/3/4职责编号说明，队员自行安排位置，不再将旧分工或体型转成新本队姓名。

预览使用现有真实模板和独立库时钟：循环末停、单RAF、菜单或全文面板暂停、离开/后台暂停、换战术销毁旧实例。减少动效、Escape/系统Back优先级、关闭期间背景锁、焦点返回和短屏内部滚动均须实际验证，概念图不作证据。

## 模块接口

- data/tactics单套定义提供bodyTypes与bodyTypeNotes，shared/templates透传；原roles/roleVersion/frames保持。
- shared/tactic-body-types.js提供按人数分类、合法性、过滤及说明的纯函数；shared/tactic-roles.js的全目录检查同时校验类别及14个组合可达，npm与Android实际入口均执行。
- frontend/src/selection/ui.js持有体型草稿、候选选择、玻璃选单和真实预览，onAction提交偏好或进入训练场；不访问持久化与主播放器。
- app统一协调队伍/库入口人数、选择页生命周期和来源清除。单独训练场选单、库卡及其播放行为保持。

## 存储与旧数据

沿用halfcourt-lineups-v1/schema2，profile可选bodyType，缺省null；没有新能力标签或个人Play。坏bodyType只归零该字段并在下一次覆盖前保原文，其他合法球队/成员/角色计划不丢。schema1继续先内存读取，首次schema2写前精确原文备份。未知schema/读取失败锁写，损坏备份/串行调用时快照/失败重试保持。

setBodyType必须提供profileId、expectedRevision，排队前捕获当前球队，执行时校验身份/版本和同人数类别。成功变更仅修改偏好、增加revision、解除旧ctx；全部成员及rolePlans保持。相同偏好无额外写入，普通档案update沿用已存bodyType，旧向导草稿不能覆盖新偏好。旧版本降级可能忽略新偏好字段，不承诺降级保留该字段，但本版本不删除旧计划。
