## 后续设计最小必填项

每个新增设计至少包含以下内容，并链接到真实文件或明确标为计划中的模块：

1. **日期与状态**：区分提案、实现中、已实现和待验收；说明文档是在实现前编写，还是基于现有实现补录。
2. **目标和边界**：具体使用场景、预期行为、人数或设备范围，以及本次未覆盖的功能。
3. **模块与接口**：依赖方向、各模块职责、公开 API、数据结构和兼容约定。
4. **状态与故障**：初始化顺序、并发操作、保存和恢复、失败时保留的数据，以及可执行的恢复方式。
5. **验收与证据**：成功条件、对应测试或人工验证步骤、已验证结果和剩余限制。
6. **协作与变更**：任务分工、共享接口、独立审查发现及处理结果；实现调整后同步更新设计和验证记录。

多 agent 协作时，先围绕范围、接口和文件边界形成共同约定，再由各自负责的模块推进实现、由集成人完成联调和验证。普通开发与修复按已授权范围直接推进；文档负责让决定和结果可检查，不增加额外审批步骤。
