# 4v4 主副通用角色与战术位置映射

日期：2026-11-05。状态：实现中，前端布局和副角色控件待讨论。

## 目标与范围

在 4v4 进攻演练中分清负责创造空间的队员与这套配合的主要得分终结者，并按球员职责匹配实际战术位置。4v4 保留独立的持球发起、掩护配合和接球策应职责。防守继续用通用号码示范；阵容schema仍为2；不改训练界面布局、也不在本任务加入副角色编辑控件。

## 角色与匹配

新配置使用 `start` 持球发起、`screen` 掩护配合、`relay` 接球策应、`spacing` 空间拉开、`finisher` 得分终结。主角色保持原本可空、可重复的行为；副角色沿用schema2的可选 `secondaryRole`，两项不得相同。自动站位全局优先最大化主角色命中，再最大化副角色命中；相同得分时按阵容顺序确定位置，未匹配位置也按阵容顺序补位。每位球员最多占一个位置。

## 旧档案兼容

旧 4v4 `mainRole: space` 是历史宽泛空间角色，不推断它属于 `spacing` 或 `finisher`，保存字段不改名、不迁移。保留 `space` 作为兼容角色，并仅在该战术过去标为 `space` 的位置继续匹配。新配置通过新的 `spacing`、`finisher` ID表达明确职责。4v4副角色可保存于 `secondaryRole`；旧界面不展示副角色控件时，普通身份保存须保留它。

## 战术位置偏好

每个 `attack-N` 位置接受一个或多个角色，构建校验覆盖全部九套 4v4 进攻战术。得分位置依据具体战术里接球、切入、顺下或外弹后负责终结的队员标记 `finisher`；纯占位位置标记 `spacing`；掩护与传接按 `screen` / `relay` 标记。保留旧 `space` 位置列表用于旧档案兼容。

## 验收

- 单测覆盖五种新角色、旧 `space` 的读写及原位置匹配、主/副优先级、队序补位、唯一球员分配和4v4副角色保存。
- 全目录构建检查覆盖 3v3/4v4 所有进攻战术和位置。
- 浏览器、APK、设备分别记录；当前前端布局和副角色控件等待后续讨论，不把未完成 UI 算作已验收。
