# 阵容档案与进攻推荐：第一版需求

日期：2026-10-22。状态：代码、浏览器与独立审查通过，1.5.0 已安装；完整真机操作待验收。任务：[HC-008](../tasks/HC-008-lineup-recommendations.md)。

## 用户确认

用户要求移除编辑页，先讨论并确认开发需求。已确认按每名队员的体型与能力点选标签，先只做进攻推荐；一个阵容一个本地档案，可以保存多个阵容，体验类似游戏编队。能力选择擅长项和可选弱项，其余按一般处理。用户接受球队档案、球员卡、阵容特点、三套推荐和动画人员联动的第一版方案。

目标使用流程：创建阵容 → 配置球员卡 → 查看阵容特点与进攻推荐 → 按本队分工播放内置动画。

以下字段上限、默认值与模块名属于开发约定，可在实现中按手机体验调整并同步本文；不将它们记作用户逐项指定。

## 页面与使用方式

底部导航改为「阵容 / 演练 / 战术库」。手机竖屏沿用一屏操作；档案列表和推荐卡片分页，配置队员逐人切换。手机横屏继续扩大球场，平板横屏利用多栏。弹窗、输入法缩小视口后的保存 / 关闭入口均应可达。

用户已批准视觉初稿：`artifacts/design/hc008-concept-v1.png`，内置 imagegen 生成，原始提示词与局部修订保存在同目录 `hc008-concept-v1-prompt.txt`。三屏依次为阵容档案、逐人标签配置、进攻推荐；深蓝 / 米白 / 橙色配色，球衣卡与队徽表达编队感，推荐候选用顶部切换一次展开一套。球场缩略图为示意，不代表推荐规则已验证或界面已实现 / 通过一屏与真机检查。

首次使用进入阵容入口，提供创建引导；已有阵容可继续最近档案。用户也能直接浏览全部内置战术，不必填写阵容。原二十套战术及动画保留，防守仍可从库中独立选取。

移除编辑视图、球场拖拽、绘线 / 擦除、步骤增删、讲解修改、撤销 / 重做及相应快捷键、菜单入口。球场用于播放、暂停、重播、速度、循环、完整步骤选择、进度拖动、讲解阅读及对手显示切换。保留现有 PNG / JSON 导出，导出内容仍为内置 Play；队员对应关系展示在演练界面，不改变兼容导出格式。

## 阵容档案与球员卡

每份档案固定为 3v3 或 4v4，分别容纳三名或四名己方队员。人数创建时确定；需要另一种人数可新建档案，避免静默删掉成员。

档案包含稳定 ID、阵容名称、内置队徽、主题色、成员和最近采用的内置进攻战术 ID。游戏感通过队徽、球队卡、球员卡和标签体现。第一版不包含成长等级、训练经验、解锁系统或综合战力评分。

| 球员信息 | 第一版约定 |
| --- | --- |
| 标识 | 档案内稳定 ID，昵称可选；留空显示队员 A / B / C / D |
| 号码 | 用户球衣号码，档案内不重复；默认顺序号，与动画职责号分开 |
| 身高特点 | 偏矮 / 中等 / 偏高 |
| 体格特点 | 偏瘦 / 中等 / 强壮 |
| 移动能力 | 偏慢 / 一般 / 灵活 |
| 擅长项 | 投射 / 突破 / 传球 / 控球 / 掩护 / 篮下终结，最多三项 |
| 可选弱项 | 同一能力集合，最多两项，不能与擅长项重叠 |

体型按常一起打球的人群相对判断，无需填写精确身高体重。未选能力按一般处理；不从“偏高”自动推断掩护、篮下终结或传球强。创建时体型和移动需要明确选择，能力可以全为一般。三名或四名成员均配置完整才生成正式推荐。

可以创建、查看、修改、切换和删除多个档案；删除需在界面明确指向具体档案。第一版成员归属于各自档案，不建立跨阵容共用球员库，避免修改一张卡意外影响其他队伍。首版容量暂定二十个档案，达到上限可修改或删除已有档案，禁止静默覆盖。

## 阵容特点与推荐

推荐只使用当前档案和同人数的十二套内置进攻中的候选，每种人数六套。八套防守不参与排名。推荐在手机本地计算，离线 APK 全部可用。

先汇总队伍的持球点、传球接应、投射、掩护、终结与移动特点，生成能追溯到具体标签的特点说明。同一份成员信息产生稳定结果，修改昵称或主题色不影响排名；修改体型或能力后重新计算。

每次优先展示三套不同战术。每套结果必须包含：内置战术 ID / 名称、推荐原因、人员职责对应、执行条件、阵容短板提醒和播放入口。说明要引用实际队员标签，不给虚构的百分比匹配度、胜率或必胜结论。

推荐规则由逐套编写的战术职责需求驱动：枚举三人 / 四人职责分配，结合能力优势、弱项和体型特点比较匹配方案。保留具体理由和缺口，稳定处理并列。硬条件不足的候选不能包装成强推荐；可作为有明确前提的备选，说明需改善的环节。若合适候选不足三套，展示实际数量并解释，避免凑数。

全为一般、没有投射优势、多人偏慢、多个同类型球员等组合均有可读结果。第一版针对己方阵容，不额外要求填写对手，也不生成新的站位或跑位数据。实际职责表、规则依据和案例见 [推荐规则](../../data/recommendations/README.md)。独立审查已核对十二套动画与典型 / 边界输出；标签权重是本项目设计推论，不是职业教练认证或最优阵容证明。

## 队员与动画联动

推荐时生成一对一映射：动画进攻职责号 → 当前档案成员 ID。例如职责 1 号由小王担任持球人，职责 2 号由小李承担掩护；不可同一人兼占两个位置或遗漏成员。

球场保留内置职责号以便对应现有讲解，同时展示昵称 / 队服号码图例。昵称长时截短显示并提供完整查看，不能挤压球场或操作。参考对手不使用本队姓名，原内置讲解按职责号解释。映射仅覆盖人物称呼和图例，不改队伍 team、球权、路径绑定或模板站位。

从推荐打开动画时使用档案当前版本，保存该档案最近选用的进攻 ID，并记录本次演练的来源引用。修改成员标签后原推荐和职责分配失效，重新计算；切换、删除档案或从库中另选战术时，旧姓名图例与映射及其来源引用及时解除，避免把旧队伍分工套到新内容。不同人数不沿用映射，防守模板不套用进攻推荐分工。

## 数据与模块边界

继续使用现有原生 JavaScript / SVG、Vite、Capacitor 与平台存储，无新增业务服务器。当前模块：

| 模块 | 职责 |
| --- | --- |
| shared/lineups.js | 纯数据结构、字段验证、稳定成员标识与输入规范化 |
| shared/recommendations.js | 纯函数：阵容特点、战术排名、人员分配、原因与缺口 |
| data/recommendations/offense.js | 各内置进攻的职责需求与解释规则，不修改原动画数据 |
| frontend/src/storage/lineups.js | 多档案读取、校验、快照保存、失败保护 |
| frontend/src/storage/lineup-session.js | 档案操作、推荐来源、双键切换与版本协调 |
| frontend/src/lineups/ | 档案 / 球员卡 / 推荐界面与表单状态 |

依赖方向为 UI → 推荐纯函数 / 档案仓库；推荐 → 阵容规范与规则数据；仓库 → 现有 platform adapter。shared 不引用 DOM、Capacitor 或持久化。

档案新键暂定 `halfcourt-lineups-v1`，保存带 schemaVersion 的多档案集合、activeProfileId、档案内 recentTemplateId，及可空的 playbackContext（profileId / profileRevision / templateId 来源引用）。存本地队员信息和内置 ID，不保存自定义 Play，也不恢复个人战术库。推荐结果及职责映射计算生成，不持久化陈旧结果。原 `halfcourt-builtin-selection-v1` 仍只含模板 ID / 步骤，保持原有战术查看进度；启动时同时校验来源引用、档案版本、templateId 和 mode，再重算映射。不匹配只恢复普通演练，不能仅因最近用过同一模板就附加队员姓名。

从库选战术、切换 / 删除档案等操作先成功清空持久化来源引用，再完成切换；清空失败时保留原上下文并提示重试，不能展示切换已完成。更新档案递增用于推荐有效性的版本。两个键无需假定原子写入，部分失败后宁可恢复普通演练，也不得误套人员；保存失败提供重试且不声称上下文已持久化。

新增档案与原清理流程分开：旧 draft / library 继续按 HC-006 定向清理，绝不扩展为删除新档案或其他设置。旧版本升级后没有档案时展示创建引导，保留合法内置选择。

读完成后再初始化写入；读失败锁定写入并提供重试，不能把未知旧档案覆盖为空。损坏数据保留原文，在替换前完成备份；可解析集合中的个别坏档案隔离并提示。写入捕获快照、按序执行、失败提示且可重试；未成功写盘时不得提示“已保存”。表单只有明确保存后替换档案；切换 / 返回时处理未保存更改。名字作为文本渲染，用户输入不拼接进 HTML。

## 验收标准

1. 三人和四人档案可创建、修改、切换、删除，昵称与标签重启保留，档案间数据独立；超过容量或重复号码给出可操作提示。
2. 擅长和弱项不能冲突，上限受控；未选能力按一般，未填完成员有明确引导，输入失败不丢失已填内容。
3. 推荐仅来自同人数内置进攻，不出现重复候选；理由对应标签，所有成员恰好分配一个职责；弱项与条件缺口可见，候选不足不伪装强匹配。
4. 覆盖全一般、缺少投射、多人偏慢、同型阵容、多人同名，以及标签变化导致排名 / 分工变化等场景。逐套规则由未实现算法的 agent 人工审查，不能只用自写规则镜像测试证明合理性。
5. 推荐直接播放；姓名图例、职责号、讲解一致，模板原始动画和球权不变；切换人数 / 档案 / 战术 / 防守后无过期映射。
6. 编辑页、修改工具和快捷键确实移除；二十套播放、步骤 / 讲解 / 对手显示、进攻防守筛选与现有导出继续可用。
7. 六种现有屏幕尺寸主页面不溢出；档案及推荐分页全部可达，手机逐人填写、键盘、关闭与返回流程清楚。
8. 本地保存覆盖读取失败、损坏隔离、备份失败、并发快照、重试与旧数据清理互不影响；不恢复个人 Play。确定性验证：推荐播放 T → 从库手选同一 T → 清来源引用写入失败 → 重启；失败时切换不得记为完成，清空成功后重启不得误恢复旧姓名，不能仅比较相同模板 ID。
9. Chrome 与纯函数 / 平台模拟分别留证；最终 APK 编译签名、设备安装与真机档案保存 / 推荐 / 播放 / 键盘 / 旋转分别记录，未做的真机项目不记为通过。
