# 训练场观看布局 · 视觉讨论

2026-11-02；任务：[HC-047](../tasks/HC-047-training-design-concept.md)。用户确定以观看完整套战术动画为主，先交付效果图。

用户随后批准效果图，[HC-048](../tasks/HC-048-training-viewing-release.md)开始正式接入。以下概念说明保留；实际实现采用真实SVG球场、原播放引擎/来源保护与四项导航，步骤卡分页改为全步骤点，当前计数仍用1 / N；标题选择复用原select。竖屏集中控制、横屏左右分区，具体短屏可达性由真实浏览器验证。

## 目标与非目标

突出室内木地板球场，保留顶部留白与冰川蓝/银灰玻璃框架。当前战术名作为卡内主标题；步骤只保留简短当前动作，播放控制集中。手机竖屏一屏，横屏球场扩大并将说明和播放区放右侧。底栏保持更衣室、训练场、战术库、我的。

本轮不改变正式界面、26套战术、播放节奏、自动播放策略、步骤跳转或存储；不加入新的训练课程功能。

该句为HC-047效果图轮的范围；HC-048获授权后仅更新训练场展示与步骤入口，不改变战术内容或播放器时序。

## 候选组成与接口

战术标题与人数/攻防标签、木地板球场、辅助显隐入口、当前步骤与讲解入口、带步骤标记的进度条、上一步/暂停/下一步、倍速/循环、四项玻璃导航。暂停图标表示效果图截取的是播放中状态。各控件仍为视觉提案，合并时间轴与步骤、标题选择面板以及横屏导航位置均须在后续交互原型中验证，尚未改变现有接口。

## 数据影响与验收边界

无新增数据、接口、迁移或服务。效果图使用内置工具生成，参考既有训练场配色与材质。静态图不证明真实动画、战术防守位置、可达性、短屏或旋转行为；不得当作正式手机截图。待用户讨论确认后，再建立实现与设备验收要求。

已交付[竖横屏静态概念](../../artifacts/design/training-viewing-concept/overview-v1.png)，[完整生成提示词](../../artifacts/design/training-viewing-concept/prompt.txt)保留。该图球场比例与路线只是示意；后续原型必须复用真实球场与数据，不能将生成图作为战术素材。

## HC-048正式布局约定

- 竖屏：原外框及上方留白 → 当前真实战术标题/原生选择控件、人数与类别 → 原比例真实SVG木地板球场 → 当前步骤标题/短讲解 → 全步骤标记/连续进度 → 居中播放与上一/下一、倍速、循环和重播 → 四项玻璃导航。横屏：大球场左置，说明及播放右置；不将SVG按两个方向拉伸。
- 原template-picker作为标题区域的真实select，保持既有仅切换同人数同类别战术以及播放时禁用；人数共享节点在库/训练场间移动，原来源解除成功后才换战术。当前标题是h1，读屏仍能找到选择控件。
- #frame-list从六项分页改为全部合法步骤的一行标记，保原data-frame-index及aria-current；点击真实停止/seek/记录对应内置步骤。#frame-counter保1 / N，步骤标题取真实讲解的首句，不写入Play。旧步骤分页入口撤下，本队人员映射的独立分页保留。
- 播放/暂停、上下步、倍速0.5/1/1.5/2、循环、重播与拖进度继续原事件和播放器；打开讲解仍暂停并分页展示原全文，旋转保留阅读位置。离页/后台暂停策略及库进入训练场自动播放保持。无新增手势或隐藏长按动作。
- 推荐来源继续显式展示实际职责/本队队员对应，人员区可点全文；紧凑屏将辅助布局压缩，不能把当前来源误标为普通演练，或遮挡播放控件。
- 加载沿现有切换busy，保留当前画面并锁冲突操作；读/写失败沿原提示与重试，不用默认档案覆盖，也不伪造空球队。内置战术始终来自真实模板，不引入假网络加载或装饰骨架。暂无讲解沿现有文本说明。

正式验收需覆盖3v3/4v4攻防、4/6/7/8步骤、推荐身份、竖横屏/短屏全控件、时间轴和步骤跳转、完整自然播放与循环，以及原有来源/存储错误与离线导出回归。静态图不替代这些检查。

HC-048已将以上布局接入1.25.0/code30并保数据安装手机；横屏推荐详情覆盖、极短屏球场偏小两项已修复，最终完整15组与独立审查通过。真实WebView96竖屏循环/暂停与双文件保持通过，物理操作/旋转与人工观感待确认，具体证据和首轮失败保留在任务记录。

## HC-049 · 战术选择视觉候选

用户随后讨论标题点开的系统下拉栏，要求先看效果图。本轮[HC-049](../tasks/HC-049-tactic-picker-concept.md)仅提供两种候选：A标题下方局部玻璃选单，B底部浮起玻璃面板。都展示同人数/同类别内置标题、当前选中态，不复制战术库动画或新增筛选层级。

点击选中后收起并沿原流程载入，点击外部/原标题取消并保留战术与步骤，均为候选交互；播放中是否允许打开、取消后是否继续、长列表/短屏布局及玻璃模糊/焦点隔离，需要选定方向后另行明确。静态图不改变现有原生select，也不构成手机更新或交互验收。

2026-11-02，[两方案效果](../../artifacts/design/tactic-picker-concept/comparison-v1.png)交付后，用户选择A标题下展。后续以标题为展开锚点、局部玻璃模糊、单列标题与当前勾选为方向；B底部方案作为历史比较稿保留。开合时长和播放/短屏策略尚未成为正式实现，不能据此修改真实战术或来源数据。

## HC-050 · 批准的选单交互

用户确认A的220ms展开、160ms收起、当前浅蓝勾选与外部关闭保留进度，[HC-050](../tasks/HC-050-tactic-picker-release.md)正式接入。当前暂停时可打开，播放中仍禁用，保持原策略；同一战术关闭即可，不重置步骤或解除推荐来源。新选择在收回后沿原安全载入，失败保旧状态并提示重试。选单不加新筛选、搜索、缩略预览或确认按钮。

标题下展按实际视口定位，局部玻璃/细边框/透明外部点击层；常规屏九行直接可见，横屏和极矮屏在选单内部滚动，主卡与导航位置保持。关闭动画期间保持背景锁，完成后恢复焦点；Escape/Back优先关闭，减少动效立即切换，旋转只重定位。无新增持久键、Play格式、模板数据、迁移或平台接口，原select保兼容接口但由新真实按钮与选项承载操作。

HC-050已接入1.26.0/code31并保数据安装手机。关闭中重复点击撤销首选问题已修，225/完整16组/36布局及独立审查通过；WV96竖屏选单开合/取消322样本、主Play和两文件保持，用户原第4步保留。硬件返回、手指及旋转仍待人工体验，首轮采样和旧库失败/测试环境恢复证据保留在任务记录。
