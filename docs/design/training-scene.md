# 训练场连续球场整卡

用户批准的视觉基准见 [HC-081](../tasks/HC-081-training-capsule-concept.md)，正式接入见 [HC-082](../tasks/HC-082-training-scene-release.md)。

## 目标与边界

训练卡片像更衣室一样由完整场景承载：木地板连续铺满边界，标题、半场线与球员、步骤说明和播放胶囊浮在同一画面上。玻璃使用浅色渐变，写实使用暗色渐变；球员和线路不随地面一起压暗。球场保持原坐标和宽高比例，短屏与横屏可重新分配卡内区域。

移除独立说明卡、编号行、重播/前后步/循环按钮。底部胶囊保留倍速、当前步/总数、百分比、节点进度与播放暂停。继续自动循环。战术库、攻防显隐、球队职责与临时交换、完整说明和标准球场导出仍沿用原入口。

不引入新战术、业务存储、账户或网络服务，也不改变标准导出球场的构图。

## 接口与播放语义

- `scene.js` 复用球场木纹定义生成独立背景SVG，ResizeObserver按卡片尺寸调整背景范围；UI中的标准球场背景由CSS透明化。原球场SVG数据、图层和导出不受影响。
- `view.js` 将真实帧映射为带可访问标签的节点按钮。节点位置为 `index / (count - 1)`，单步为0。当前节点与已过节点分别显示环和明暗；同一次战术中的节点保留DOM，以允许跨节点拖动和键盘焦点保持。
- 时间线 `--training-progress` 由真实连续位置生成。编号、标题、摘要与完整说明使用该位置的floor帧，并沿用本队号码替换规则。
- 节点点击暂停并精确定位。拖动原生范围控件或从节点起拖均暂停后连续寻址，拖动松手保留连续位置。点击播放/空格暂停也保留连续位置；从最后一步继续播放重新开始。
- 界面帧调度、速度和循环时钟继续由 `player.js` 管理；来源切换、后台停播与失败保护继续由 `app.js` 管理。

## 数据影响与验收

没有新增存储键、schema或迁移。战术进度仍只保存内置战术与合法整数步骤，连续位置在持久化时以当前floor帧保存。保留球队档案及角色方案。

验收覆盖双外观、多尺寸、全部战术节点、连续拖动/暂停/循环、真实帧和说明同步、本队映射、切换与导出。浏览器、APK编译、保数据安装、真实WebView和用户手动体验分别记证据。
