# 战术角色认领 · 需求讨论

2026-11-02；任务：[HC-051](../tasks/HC-051-tactic-role-design.md)。用户明确整体替换旧能力标签配置和自动推荐，改为选战术后球员认领本套职责，并覆盖所有现有与后续新战术。本文为新方案设计，正式1.26.0尚沿用旧流程。

## 目标与非目标

目标流程：创建球队基本身份 → 浏览/选择战术 → 查看本队各职责的具体任务 → 指定/认领队员 → 按本队演练。保留本地球队档案、姓名/球衣号码/NBA球队风格、多档案、全部内置动画、3v3/4v4与离线APK。移出体型/能力自评、擅长弱项及自动排名/自动分工产品流程。

不引入在线抢位、多用户同步、自动生成战术或个人Play编辑。将来全场/5v5可以按实际人数扩展，本轮不宣称已支持。角色描述按本套实际配合编写，不把队员永久绑定为控卫/中锋。

## 全覆盖的数据要求

每套战术随自身定义提供角色元数据：稳定roleId、动画棋子ID、短名称、整套配合的一句话职责、角色定义版本。关键阶段提示stepHints可选，填写后必须对应合法步骤/本队角色；不要求每名球员在每帧重复填文案。进攻对应本队attack，防守对应本队defense；对手只是示范。一个角色可在不同阶段执行不同动作，完整职责应覆盖该变化，不能只按第一步站位命名。相似功能可用职责号/初始方位区分显示，身份仍按稳定ID。

每套角色集合与全部帧中本队棋子集合一一对应：人数一致、无缺项/重复/跨阵营、棋子ID稳定存在；球和无主跑位线不是独立角色。文字名仅供显示，绑定按稳定ID，不能依赖数组顺序、球衣号码或可改昵称。

新增战术必须同时交付动画、全部本队角色及整套职责，统一验证从同一战术目录枚举全部注册战术，不能维护一份会漏项的手动白名单。缺角色/无对应棋子/人数不符/空职责/版本无效时，检查失败，不能作为完整可认领战术发布；不自动回退为仅“1号/2号”来掩盖漏配。该检查必须进入实际npm run build和android:build入口；目前Android脚本不会调用npm test，只新增单元测试不足以成为发布门槛。自动检查保证结构，独立内容审查核说明与实际掩护/传球/轮转一致。

## 球队分工与动画

保存按球队ID＋战术ID＋角色定义版本分组的roleId→成员ID分配。一名成员不能在同一套战术兼占两位；职责未认领时明确空位，可以继续看通用示范，不能显示“按本队演练已就绪”。换战术可用另一套分工，不改变队员身份。已认领角色调整应明确交换/解除，避免重复或悄悄挤走别人。

战术改名、目录重排和纯文案修改不改变稳定角色ID；角色身份/棋子绑定、人数或职责语义实质改变时提升角色定义版本，保留旧分工待重新确认，不自动套给新角色。结构变更可由校验辅助识别，语义改变仍须内容审查。更换成员或删除球队只影响对应引用；修改昵称/号码用成员ID继续关联，不以球衣号冒充动画职责号。

档案revision继续用于并发写保护和当前来源一致性；认领有效性单独依据稳定成员ID与角色定义版本，不能因纯昵称/号码修改让所有已认领分工失效。当前session任何update都会提高revision并清来源，这部分需要正式实现时明确调整并测试。

## 迁移与模块边界

旧档案保留球队和成员稳定ID/姓名/号码/球队风格；能力标签退出UI/推荐，原文在可靠迁移前保留备份，不按旧标签替用户确认新职责。现有推荐来源playbackContext不能当作手动认领已确认。继续先读后写、未知版本锁写、调用时快照/串行保存、写失败不表面成功和旧Play/内置选择格式兼容。

存储schema/键的具体升级或旁路策略、原子切换与失败重试需在实现前另定并测试，不在本次讨论直接变更。角色与校验放data/shared，页面只呈现和发起认领，platform/storage职责保持原边界；不将DOM/本地存储依赖放shared。

已核实现约束：shared/templates当前解构只转发固定字段，部分helpers也是位置参数接口；validateLineup也会裁掉未声明字段，仓库/session限进攻推荐来源。因此不能仅给单套文件或旧profile随意追加roles字段；后续必须统一模板透传、纯校验、进攻/防守来源和可靠迁移。旧能力文本可用于迁移前原文备份，不能继续作为新流程的隐性排序/自动认领依据。

## 验收方向

全部现有战术逐套对应角色，实际人物ID/阵营/帧一致；以后添加或删除/重排模板也由同一遍历检查覆盖。负例包括缺/重角色、空任务、错阵营、悬空棋子、重复成员和旧版本失效。正例包括未认领通用播放、三/四人完整认领、两套不同分工、成员改名不失联与能力标签无需填写。

最终需独立内容审查、真实浏览器分工/切换/动画及迁移读写故障、APK和手机分开验收。本轮只做只读清点与设计记录，不构成这些实现验收已完成。

## HC-052 · 减少换战术配置的视觉候选

用户担心分工过细导致只跑一套战术。主控提出：先确定本次上场成员与动画编号，切换同人数战术时默认沿用身份对应，展示新战术具体职责，必要时显式交换。用户要求先出图，[HC-052](../tasks/HC-052-tactic-role-flow-concept.md)以三屏说明该候选，并不表示用户已批准沿用规则或放弃逐战术覆盖。
