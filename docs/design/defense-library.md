# 独立防守战术库设计

日期：2026-10-22。在实现前建立。任务：[HC-007](../tasks/HC-007-defense-library.md)。

## 独立内容

按用户纠正后的目标，防守是独立战术类别，不是某个进攻模板的应对选项。每种人数分别提供半场盯人、区域联防、夹击防守、协防轮转，每套六步：初始分工、移动、交接 / 补位、后续移动和恢复阵形。进攻队员只作为对手参考，以球的位置和移动说明防守站位，无进攻模板绑定。

按日常半场训练示例设计，不宣称模拟对抗结果或适用于所有竞赛规则。中文讲解描述防守人当前分工与下一动作；球权、传球、路线匹配相邻快照，蓝方运行路线使用 defense-* ID。

## 元数据与持久化

template.kind 默认 offense，新增 defense；仅包装元数据变化，Play / 引擎坐标 / 导出结构保持兼容。来源 ID 可推导 kind / mode，因此选择键仍为二字段。原十二套进攻定义、顺序和默认示例保留。进入防守模式不恢复个人库或临时编辑持久化。

## 一屏呈现

库内「进攻 / 防守」切换，人数仍由全局选择；卡片含真实初始站位缩略图、名称、分类与难度，加载后在播放区显示步数。防守色为深蓝，播放按钮维持橙色。库筛选与实际球场来源分离，筛选不会隐式替换当前演练；选卡片才加载，回演练。

防守模式：蓝色防守球员 / 路线突出，橙色对手淡化；原开关文案改「显示对手」，关闭后隐藏橙方及其球，不隐藏蓝方。进攻模式保留原「显示防守」行为。手势解析遵循实际可见球队，蓝方可以绘制有 actor ID 的路线，观看页仍禁止误拖。

SVG 保持完整半场比例，蓝色强调不扩大逻辑命中范围；手机 / 横屏 / 平板继续固定一屏。长讲解仍按实际空间分页。

## 验证

数据测试按 kind 分组覆盖数量、唯一 ID、独立构建、球员阵容、路线、球权及真实插值；原进攻专项测试继续覆盖原数据。浏览器遍历两种分类和人数的全部20套，验证筛选不加载、选择恢复、对手开关、蓝方绘线、导出和六屏布局。独立审查具体防守分工与动画，不以校验合法代替战术表达。APK 与设备结果单独记录。

实现后的可见性补充：动画插值会暂时清空球的 holderId，显示策略应使用相邻真实帧球权；真正自由球保持可见，隐藏对手的球在播放和拖动进度时均保持隐藏。修复及独立复验见 [HC-007 审查](../reviews/HC-007-defense-library.md)。
