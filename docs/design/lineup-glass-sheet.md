# 阵容主卡片与玻璃任务面板

2026-10-23。状态：效果与范围已获用户确认，[HC-021](../tasks/HC-021-lineup-glass-release.md)已接入正式1.13.0并安装指定新机；代码/浏览器/APK及真实WebView程序检查通过，完整物理操作待验。预览任务为[HC-020](../tasks/HC-020-lineup-glass-sheet-preview.md)。依照[统一逐屏规范](unified-screens.md)与HC-019顶部留白继续迭代。

## 目标与边界

将「我的阵容」标题纳入显示「先组一支自己的球队」的同一主卡片。空态内容为更衣柜/说明/创建按钮；有档案时沿同一容器呈现球队、柜位与成员信息。页面保留明显顶部留白及底部玻璃导航。

后续用户要求主卡缩小、更衣室只保留一个橱柜，并在页面顶部显示项目名称与图标。采用现有HALFCOURT / 半场篮球战术板与批准的库里图标；顶部先留白再放品牌区，中部是较紧凑的单柜主卡，下方留呼吸空间，玻璃导航固定。主卡内继续保留「我的阵容」，空态与有阵容态均不显示相邻柜。HC-020先验证独立预览，HC-021仅正式更新阵容页；其他页面后续采用同一品牌区方向。

柜位外观为更宽矮的开放式球员柜：哑光灰蓝外框、稍深的凹入柜腔、顶部姓名牌（空态为等待入队）、带挂钩与真实镂空的浅木色衣架、轻暖白照明、柜内木座板和下层储物格。有阵容时球衣居中，保留可读姓名/号码；不用实心三角衣架或外伸长凳。HC-020为预览视觉更新，HC-021已接入真实档案柜位。

点击创建，背景逐渐变暗和模糊，一块带冰川蓝的半透明玻璃任务面板由底部缓升，约450ms无弹跳，停在手机上部15%–20%以下。背景先稳定、面板尾段减速；关闭反向。低高度/横屏可调整占比保证字段和按钮，减少动效时直接静态呈现。打开期间背景/导航不可操作；关闭后恢复触发焦点。

任务1建立球队（名称/3v3或4v4），任务2选NBA球队与球衣，任务3配置3/4名成员（资料/体型/擅长/可选弱项）。所有任务在同一面板中完成，顶部进度、底部上一步/继续/最终动作固定；只有已完成任务可以回看，弱项不强制选。输入保留，清晰显示每个队员待配置状态，不虚构战力。

关闭/遮罩/Escape统一处理当前草稿；有改动先显示可见的继续/保留会话草稿关闭/放弃。保留不表示可跨进程恢复。第一版不做下滑直接关闭。

## 接口与数据

HC-020预览为file直开的原生HTML/CSS/SVG/JS，NBA资源来自本仓库；不导入正式业务模块，不访问网络或任何存储。独立`window.glassPreview`供截图控制与状态核对，键盘与指针均能操作；背景采用不可交互/焦点隔离且有降级机制。

预览最终按钮只能更新当前网页会话内的演示阵容，并明确说明没有写入本机。用户已确认正式版采用最后一次保存：HC-021让create接收完整成员快照，单次写入新档案，写失败保留创建草稿，不先保存空档。沿用现有schemaVersion 1/存储键、旧档案和update版本保护，不改变推荐来源清除的协议。新建需完整体型，已有不完整档案仍允许显式保存；旧无NBA档案保持中性兼容。

正式版由`lineups/ui.js`管理三任务与相互隔离的创建/编辑草稿，`sheet.js`/`sheet.css`提供原生dialog壳、450ms浮起、视口高度、关闭与背景控件禁用/焦点返回；app通过isModalOpen/onModalChange接入导航、嵌套说明、Escape、Android返回与播放暂停。关闭动画中控件锁定。柜位占100%视口，左拖下一位/右拖返回。详细接口和存储边界见[架构](../architecture.md)。

## 状态与验收

空卡/面板关闭；面板打开中/已打开；任务字段缺失；各队员未完成；关闭草稿确认；演示完成后有阵容卡。错误贴字段，不以假网络/假加载制造任务感，切任务不丢输入；不增加个人战术或账号。

Chrome核对450ms动效中间态、遮罩/模糊与面板位置变化、点击/键盘隔离、关闭确认、减少动效，以及390×844、360×640、844×390、1024×768按钮完整性。效果图与程序检查同真机/生产流程验收分开；独立审查记录真实发现与修复。
