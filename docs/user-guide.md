# 球搭 · HOOPAL

本地运行的 3v3 / 4v4 战术动画工作台，支持电脑、手机浏览器和 Android 离线 APK。首次开发需要安装 npm 依赖，运行资源随应用打包，无远程字体或外部 CDN。

## 运行

开发环境先在项目根目录运行 `npm ci`。之后 Windows 双击根目录 `start.cmd`，或执行 `npm start`，保留命令窗口。电脑打开 http://localhost:4173 。需要 Node.js 22.12 或更新版本，启动入口会自动构建页面资源。

Android APK 安装后直接打开应用，不需要电脑服务或同一 Wi-Fi；构建说明见 [Android 离线版](android.md)。

应用在手机桌面显示为「球搭」。打开时，品牌完整停留1秒，圆角画框再用1.1秒展开到当前更衣室，最后0.3秒交接，全程约2.4秒，可点右上「跳过」。从后台返回和页面切换不会重播；开启系统减少动态效果时直接进入。读取较慢会显示真实读取提示，跳过动画也会等待档案读取完成，读取失败可在页面重试。更新继续沿用原应用身份和本地资料，无需卸载。

手机与电脑连接同一 Wi-Fi，在手机浏览器打开启动窗口打印的 `http://电脑局域网IP:4173` 地址。当前开发环境的地址为 http://192.168.110.51:4173 ，电脑更换网络后以启动窗口的新地址为准。保持电脑和服务运行；如系统防火墙询问，允许 Node.js 在当前专用网络中访问。关闭窗口或 Ctrl+C 停止服务。

## 创建自己的阵容

底部「更衣室」显示 HOOPAL / 球搭品牌、当前球队及单人更衣柜；「换球队」进入「我的」中的「我的球队」。没有球队时，空柜引导去创建。每份档案固定三名或四名队员，最多二十份；球队每页三张卡，包含队徽、名称、人数、成员和当前使用标记，更多球队页内翻页。

四页玻璃主卡使用一致的宽高区域与边距，更衣室的单柜保持自身比例；手机横屏和平板采用相应分栏，顶部留白和底部导航保持。

在「我的」的「我的球队」区域点「创建球队」，玻璃任务面板约 450 毫秒从底部浮起，背景渐暗、模糊。三个任务都在同一面板完成：

1. 填写队名，选择 3v3 / 4v4。
2. 选择 NBA 球队。手指左滑切到下一队、右滑返回，松手减速吸附；也可点两侧队徽或箭头。队名、队徽和代表球衣同步预览。「全部球队」中30队分三页，每页最多十二队，点选后返回转盘，返回键也可先退出列表。没有选队时显示中性占位，新建需明确选择球队才能继续。选择仅更新草稿，最终保存才写入本机。
3. 逐个配置队员的资料、体型、擅长和可选弱项。所有队员的身高、体格、移动均需选择，擅长和弱项可以留空。

三步共用固定的顶部任务进度与底部操作。第三步上方突出当前队员的大球衣、姓名和号码，下方切换资料、体型、擅长、弱项；点成员按钮、左右箭头，或在球衣上左拖下一位、右拖返回。姓名和号码随输入同步预览，取消滑动保持当前队员。步骤横移约320ms，成员球衣与资料同移约280ms；系统减少动态效果时立即切换。短屏收紧球衣尺寸，横屏左右分区，输入时保留字段和底部操作。

「继续」和已到达的任务可用于往返，切换任务、球队或队员都保留当前输入。前两步不创建本地档案，最后点「完成并保存阵容」才将全队资料一次保存；成功后进入更衣室。保存失败面板保持打开，可以修改或重试。创建后人数不能直接改，其他人数另建档案。

点球队卡直接选用并进入对应更衣室；保存失败保留原队和「我的」页。重新打开当前队会保留合法的战术人员对应。卡片右上角「⋯」单独打开管理菜单，可配置球员、修改球队名称、更换NBA球队或确认删除，不会顺带切换当前队；编辑完成或取消返回来源页面。只翻页、浏览或打开菜单不修改当前球队。

档案读取失败时，更衣室和「我的」都显示读取提示及「重试读取」，恢复后再选择或创建；不会把无法读取的档案显示为零份，也不会自动创建空档案覆盖原内容。

「我的」顶部为球搭账号卡，下方提供「同步与备份」「设置」「关于球搭」。账号与云备份目前尚未开放，点击会打开玻璃说明面板，不要求输入密码，也不上传球队。现有球队管理、推荐和战术演练继续在本机离线使用。关闭、遮罩、Escape或返回可收回说明面板，再回到原操作位置。

更衣室展示当前球员：手指向左拖（←）切到下一位，向右拖（→）返回，也可用箭头或圆点切换。第一位没有上一位，最后一位没有下一位，提示随位置更新。姓名、球衣号、体型与能力随选中成员更新，点「配置球员」直接配置当前成员。各阵容分别记忆本次查看位置，切换查看不会保存配置或改变推荐来源；重启后查看位置重新开始。长姓名、标签可点开查看完整文本。

逐个配置队员，在「资料 / 体型 / 擅长 / 弱项」之间切换：

- 昵称可留空；球衣号码为 0–99，同队不重复。
- 身高：偏矮 / 中等 / 偏高；体格：偏瘦 / 中等 / 强壮；移动：偏慢 / 一般 / 灵活，按一起打球的人群相对判断。
- 擅长最多三项，可选弱项最多两项：投射、突破、传球、控球、掩护、篮下终结。同一能力不能两边同时选，未选按一般。

已有档案点「配置球员」进入同一面板，直接打开当前成员配置；也可回到前面任务修改队名或球队，点「保存配置」后才写入本机。旧的未完整档案仍可编辑、显式保存；旧档案未选 NBA 球队时保持中性球衣，不会自动分配球队。各档案的草稿和球队互不影响，推荐仍要求全队体型与移动配置完整。

面板打开及关闭动画期间，背景页面和底部导航不可操作。关闭按钮、遮罩、Escape 或返回键统一处理当前草稿；新建或有修改时可选择继续、保留会话草稿关闭、放弃。保留后本次应用会话可重新打开继续，草稿只在内存中，重启应用或进程结束后不会恢复。放弃不改变已保存档案；长姓名和错误说明可点开分页读完，返回先退出说明，再处理面板关闭。

球衣采用一队一套代表配色和胸前字样，所有成员同步，昵称和自己的球衣号保留。选队不会改变整体界面配色、队员能力或战术分工；演练棋子仍显示职责号与攻防颜色。队徽随应用离线打包，无需联网下载。删除需确认具体阵容，其他档案不受影响。

## 看进攻推荐

在更衣室点「查看进攻推荐」。每名队员的体型和移动均已选择后，按当前已保存信息推荐最多三套同人数的内置进攻。顶部切换候选，正文切换「特点 / 理由 / 分工 / 提醒」，每项可分页读完。

「适合尝试」说明当前标签与职责相符；「有条件备选」会解释关键能力未标优势、明确弱项或移动负担。未标优势不等于不会，体型也不会自动变成技能。推荐仅帮助安排本队训练分工，不预测对手、命中或胜率。具体规则和资料范围见 [推荐规则](../data/recommendations/README.md)。

点「按本队分工演练」载入原始内置动画。球场数字始终是战术职责号；人员图例分别列出昵称和真实球衣号码，例如「职责 1 → 小王 · 球衣 7 号」。点图例可看完整信息，四人分工分页全部可达。

修改阵容能力后重新推荐；切换档案或从战术库点击「进入训练场」会解除旧人员对应。只查看卡片和切换筛选不会解除。没有档案也可以直接看内置战术，防守战术仍独立提供，不参与第一版进攻排名。

## 看战术动画

底部切换「更衣室 / 训练场 / 战术库 / 我的」，新页面从目标导航按钮中心柔光展开，约600毫秒，先轻柔起势、再展开、最后淡出；快速点击以最后目标为准，系统减少动态效果时立即切页。主页面采用一屏布局，球队和长文字分页、配置逐人分段。

仅更衣室显示顶部品牌。训练场和战术库保留上方留白，内容在下方单张主卡中展开。训练场卡内集中战术选择、对手显隐、球场、步骤、讲解和播放控件；手机横屏及平板将球场放在左侧，回放和步骤放在右侧。人数选择在当前页面卡片标题旁，导出「⋯」位于训练场卡内右上角。

在战术库切换人数只筛选卡片；回到训练场时，人数显示当前已载入战术的实际人数。在训练场更换人数会载入该人数的内置示例。页面排版调整沿用原有 600 毫秒导航转场、450 毫秒组队面板和本地记录规则。

1. 进入战术库默认显示当前人数的全部战术标题。可切3v3/4v4、进攻/防守；点标题展开球场即以1倍速循环播放完整战术，末帧停1秒再重头；点球场暂停/继续，右上角标与细进度线提示状态。再点同一标题收回，换卡会自动收旧卡并从头播放新卡。每种人数9套进攻标题都在同一页，防守4套也直接显示。常规竖屏展开时保留其他标题，球场和说明左右排；较矮屏幕只展开当前卡，点标题旁「收起 · 返回列表」回到全部标题。横屏和平板将展开卡与其余标题分区。换人数、攻防或重新进入库全部收起。只浏览不会替换当前演练、进度或本队人员对应。
2. 点卡内「进入训练场」才载入正式演练并从头自动播放。卡内循环只供浏览，保留当前训练场与人员对应；收起/换卡停止，重开从头，后台暂停后需手动继续，旋转不重置当前进度。进入训练场后可暂停、重播、选择0.5–2倍速度、循环和拖动进度。暂停或结束拖动停在最近完整步骤。球场顶部仍可手选当前类别同人数的示例；若解除旧来源失败，保留卡片及原训练场供重试，卡内预览停在当前位置，可点球场继续。
3. 用步骤编号或上 / 下一步选择阶段，步骤仍按真实战术显示四至八步，步骤分页保留；点「讲解」分页查看完整说明，旋转保留阅读位置。本队人员图例也保留分页与完整信息查看。
4. 进攻可隐藏防守；防守模式突出蓝方和蓝色路线，可隐藏橙方参考队员及其球。

「低位分切」的蓝方示范固定人盯人、不换防：蓝1跟随1号，蓝2接近掩护后绕挡追2号，蓝3在低位有限补位再回收。可在训练场打开「显示防守」，重点看第3–4步的追防和传球窗口；这是预编排的一种应对，不保证切入必然形成空位。

| 人数 | 进攻 | 防守 |
| --- | --- | --- |
| 3v3 | 高位挡拆、传切配合、无球背掩护、手递手配合、挡拆外弹、底线反跑、低位分切、假掩护顺下、无球外弹接投 | 三人半场盯人、三人一高两低联防、三人边线夹击、三人协防轮转 |
| 4v4 | 四人传切、挡拆弱侧拉开、双掩护接球、高低位配合、突破分底角、西班牙挡拆、弱侧锤子配合、下掩护接手递手、掩护者再获掩护 | 四人半场盯人、四人二二区域联防、四人底角夹击、四人协防轮转 |

共二十六套。原四套进攻各四步，原其余十六套各六步；新增六套分别为7、6、7、7、8、8步。动画不模拟投篮命中、真实身体对抗或自动抢断。1.5.0 已移除战术编辑，球场不会因拖动而改变站位，也不能修改步骤和讲解。

## 本地记录与导出

阵容档案在手机本地保存，与内置模板 ID / 步骤分开。首次升级保留原合法内置选择；旧个人战术库、草稿和对应备份继续按用户要求清理，新阵容档案不在清理范围。

读取失败会保护原档案并提供重试，保存失败明确提示，表单内容保留；不要把失败提示当作已保存。损坏档案原文在替换前备份，未知版本不会直接覆盖。

训练场主卡右上角「⋯」可导出 PNG 或 JSON，内容仍为内置战术；本队图例在界面查看，不写入兼容 Play 文件。APK 用系统分享交接，取消不算导出成功，外部文件不受旧个人库清理影响。没有个人战术库、战术新建或导入入口。

弹窗有关闭按钮，网页 Escape 可关闭；阵容配置面板先按上述草稿流程处理。空格仅在训练场播放 / 暂停，输入时不触发。Android 返回键优先处理当前弹窗或阵容面板，再处理播放、输入和阵容子页，最后回到更衣室首页 / 桌面。

## 开发与验证

- `frontend/`：响应式界面、SVG 球场、触屏交互、播放、平台接口、内置选择与阵容档案。
- `shared/`：战术状态、历史、输入校验、动画插值和模板生成。
- `frontend/src/workspace/`：页面切换、弹窗、视口内分页与长讲解测量。
- `data/templates.js`：内置战术汇总；`data/tactics/` 按人数保存具体站位、路线和讲解；data/recommendations/ 保存进攻职责规则。
- `backend/`：仅用 Node.js 内置模块的静态服务。

在项目根目录运行 `npm test` 构建并验证引擎、存储、平台接口和 HTTP 资源路由。构建后运行 `npm run test:browser` 会自动启动临时服务，用本机 Chrome 检查桌面和手机交互，并在 `artifacts/qa/` 输出截图；可通过 `CHROME_PATH` 指定 Chrome 可执行文件位置。目录详细说明见 [架构说明](architecture.md)。

本项目按用户要求采用多 agent 协作：产品 agent 评审分步快照与交互边界，状态引擎 agent 实现动画与数据校验，界面 agent 实现视觉与响应式布局，主 agent 负责交互整合、本地与手机访问及浏览器验证。
